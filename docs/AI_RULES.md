# AI RULES

1. Read docs/AI_MEMORY.md before coding.
2. Inspect the repository before making assumptions.
3. Never rewrite unrelated working code.
4. Keep controllers thin.
5. Put business logic in Services.
6. Use Form Requests for validation.
7. Use Policies for record authorization.
8. Use API Resources for API responses.
9. Use transactions for multi-step inventory mutations.
10. Preserve asset location history.
11. Never bypass backend authorization.
12. Never expose private attachments directly.
13. Reuse existing components and services.
14. Do not create duplicate routes/models/components.
15. Run relevant tests/checks after changes.
16. Update TODO.md and CHANGELOG.md after meaningful work.
17. Do not commit or push unless explicitly requested.
18. If requirements conflict, stop and report the conflict.
19. Never treat documentation as proof that a feature is implemented.
20. Actual repository code is the final implementation truth.
